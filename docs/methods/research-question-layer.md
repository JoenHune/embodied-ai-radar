# 研究问题层方法

本文保留问题层的早期设计和人工判断方法。v3 继续使用 Q0–Q10 作为正交问题轴，但把数量、具体命题生命周期和 E0–E4 实验证据分开展示；历史 A–D 判断不直接换算为 v3 证据等级。最新结果见[月度问题轴](/monthly/)与[研究趋势](/trends/)。

## 为什么不改 D1–D15

D1–D15 是正式纳入工作的唯一主分类；主方向不确定的记录另留复核。问题层是多标签镜头：触觉、失败数据、软硬件共设计和主动感知天然跨越多个主方向。如果直接改主分类或分类顺序，会把历史曲线变化与真实研究变化混在一起。

## 早期自动层（迁移背景）

- 数据源：已纳入的 arXiv 母库记录。
- 日期：首次提交 v1。
- 匹配：标题与摘要对公开词表做不区分大小写的子串匹配。
- 输出：`data/research-question-evidence.json`，记录论文命中的 Q 与具体词项。
- 限制：高召回计数只能表示相关工作密度，不能证明研究命题成立。

## v3 的问题轴与命题证据

当前 Q 轴在统一 canonical work 上按标题/摘要与版本化词表匹配，不再局限于 arXiv 母集。技术报告、正式版本和项目产出均可进入同一证据库，但纳排与组织归属仍须分别通过。

Q 命中和议题数量只负责发现；具体命题必须有支持、反对或中性的证据记录，明确实验设置、对照、指标、局限与原文出处。自动编辑器可以产生 source-bound draft，却不能自行将语义推论标成 verified。机械引文校验与显式语义审阅是两个步骤。

命题生命周期只使用可追溯、已审阅的支持证据，并保留反例。共享 benchmark、仓库或作者不能自动合并来源，更不能算独立复现；不同来源簇也不自动证明独立实验。完整规则见[趋势判定](/methods/#趋势判定)和[命题证据记录](/api/v1/signal-evidence.json)。

月度默认只使用截至该月公开的证据；“今天回看”保持原有研究 cohort，另外计入后来的验证。暂行月、未知日期与无数据值不能制造虚假增长或下降。

## 人工判断层

下表保留早期研究判断方法，不是 v3 自动执行的 E 等级表，也不与具体命题生命周期一一对应。

| 等级 | 使用条件 |
|---|---|
| A | 多团队或严格同行评审已确认路线，但不代表具体科学问题完全解决 |
| B | 过去 12 个月出现多个独立研究簇，仍缺统一评测、跨平台复现或成本对照 |
| C | 高价值早期假设，证据主要来自少量预印本、系统原型或内部经验 |
| D | 反证增加、缺少独立跟进，或结果只剩命名和单一 demo |

P0/P1/P2 只表示战略依赖顺序，与 A/B/C/D 外部证据等级相互独立。

## 升级与降级

- 升级优先看真机、独立团队、正式发表、跨硬件复现和决定性指标。
- 只有关键词数量增加而没有新能力，不升级。
- 反证条件被触发、连续两个季度没有独立跟进或成本不可接受时降级。
- 安全、评测和软硬件变量可以成为关键门槛，但不会仅因“论文少”被误写成弱方向。
