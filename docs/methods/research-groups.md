# 研究组归属与周度监测方法

## 实体层级与证据

- 母机构只做向上聚合，不代表具体研究路线。
- 研究院/事业部、实验室/PI 组和独立研究公司可以成为跟踪单元。
- 论文合作组不是持久 organization。
- G1 为官方实验室论文/项目页或论文直接声明研究组；G2 为论文作者与带时间的官方成员关系重建，不能只使用今天的 roster。
- G3/G0 保留在复核或母机构观察层，不进入具体组的正式研究动态。

母机构、研究院/事业部、实验室/PI 组、独立研究公司与论文合作关系分别建模。组织身份、负责人、父子关系与有效期各有来源；未核实的任期保持未知，不从最早论文日或网页当前状态推算。

必要的边界包括：NVIDIA 署名不能自动归为 GEAR，CMU 署名不能自动归为 RI 或某个 RI 实验室；GEAR/Cosmos、Amazon FAR/Amazon Robotics、RAI Institute/Boston Dynamics、Physical Intelligence/MPI-IS 同名部门均保持独立。现职与历史论文归属不互相覆盖，联合工作可出现在多个档案，但全局只计一个 canonical work。

## 归属与研究相关性是两道门

G1/G2 只回答“这项工作归谁”，不回答“是否属于本雷达的研究范围”。正式活动还必须是 included；已归属但 candidate、manual_review 或 excluded 的记录仍可在完整集合与待复核集合中查看，不能悄悄删除。

高信号工作若缺少可靠执行组归属，会进入[显眼的待归属队列](/methods/coverage)，不是按作者聚类硬配一个实验室。论文只给学校/公司时可登记 G0；当前成员名单、GitHub owner、域名、招聘广告和作者姓名本身不足以升级为 G1/G2。

## 每周窗口

已实现的编排接口安排本机周一北京时间 00:00 更新，远端周一 04:00 检查上一完整 ISO 周快照是否缺失并兜底。是否已安装和实际运行必须查看调度及 CI 记录，不能由代码存在推定。

周报覆盖上周一 00:00 至周日 23:59。确切时间点保留时区，页面以 Asia/Shanghai 展示；运行时间、来源采集截止、首次发现时间和周报覆盖窗口分开。只有月份的发布日期不强行分配到某一天或某一周；战略观察可按首次观测日收录，但明确注明发布日期未核实。

周报首先列研究变化，再单列 Demo、招聘、组织或人员变动等战略观察。无可升级研究信号时仍保留简短周报和信息缺口。重复运行复用 ISO 周键；网站成功不等于飞书成功，飞书失败独立记录待补发，不回滚网站。

## 不做跨组排名

页面只展示每组的时间线、方向变化、证据类型、开放资产、真机与合作关系。论文数量、Demo 和部署规模不压缩为一个不可比较的总分。

## 自动化边界

官方 publications/projects 页面可以提供直接归属证据，但被采集到、URL 能访问或标题匹配成功，并不自动证明其内容已逐项核实。身份登记与实际来源健康检查分开；只核查身份的来源保持 unverified，不冒充一次成功的自动采集。

T0/T1 来源按七天、T2 按三十一天检查周期核对。连续两次失败，或两个检查周期未核验，显示 stale warning 并保留历史。详细分母、检查日期和失败原因在[来源覆盖](/methods/coverage)中公开。

研究组按 T0 核心、T1 前沿和 T2 发现池组织，不设置固定论文数量排行榜。[组织目录](/organizations/)保留每个跟踪单元，[合作关系](/organizations/collaboration)只连接有共同归属证据的 work。无法可靠归属或主题相关性尚未通过的记录保持待核验状态。

联合署名、共享仓库与共同使用 benchmark 不是独立复现。合作网络只表示合作；E4 与命题成熟度另按[证据规则](/methods/#证据等级)判断。

## 仍需持续验收的目标

关键组公开工作完整覆盖、T0 回归样本召回率至少 95%、高信号归属至少 90%、初创企业技术报告持续维护，仍是交付目标。缺少独立发布金标准时，召回率保持未测量；缺少可靠归属时保留完整分母和待核验项，不用缩小范围取得高覆盖率。

实现依据：`organization_coverage.py`、`ingest_attribution.py`、`run_weekly_v3.py`、`install_weekly_launchd.py` 与 `publish_group_weekly_to_feishu.py`。
