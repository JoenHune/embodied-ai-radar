# 方法与数据

具身智能研究雷达 v3 将公开来源、研究工作、相关性、组织归属、时点证据与中文研究判断分层保存。数量由确定性程序计算，语言模型只编辑给定证据包，不能决定基础计数或自行升级评审、能力和研究组归属。

本文按当前实现同步；运行版本、语料截止、计数和来源缺口以[公开 manifest](/api/v1/catalog-manifest.json)、[覆盖审计](/methods/coverage)与每月 revision 为准。代码可运行、某次测试通过与生产系统已启用是不同状态。

## 数据链路

  <li><strong>公开来源与原始观察</strong><span>保留来源 URL、原始标题、内容、日期精度、采集时间与字段出处</span></li>
  <li><strong>规范研究工作</strong><span>CanonicalWork 与 Manifestation 连接同一研究的预印本、正式版本和公开产出</span></li>
  <li><strong>相关性、分类与归属</strong><span>included / candidate / manual_review / excluded 与 D/Q 标签、G0–G3 归属分别判断</span></li>
  <li><strong>按月可用证据</strong><span>按来源实际公开时间计算评审、开放资产、实验能力、趋势命题和修订</span></li>
  <li><strong>检索与研究编辑</strong><span>公开 JSON / SQLite / Pagefind；基于证据包生成中文编辑和待语义复核的命题草稿</span></li>
</ol>

`data/catalog/` 中规范化、分片的 JSONL 是事实权威层；来源配置与审核补充文件是显式导入输入，不是另一套网站事实库。`data/editorial/` 独立保存中文编辑、本地化缓存和命题证据审阅记录。SQLite、静态 API、搜索索引和网页都是派生物，不在派生文件中人工修正事实。

迁移只用于首次建立权威库；之后通过增量导入保存新增来源、别名和修订。普通导出与网站构建只读权威库，不重新迁移、不采集网络，也不调用模型。完整源记录对账见[迁移报告](/api/v1/migration-report.json)。

## Canonical work 与版本

稳定 ID 的优先顺序为 DOI、去版本 arXiv ID、官方报告/项目 ID、标题—作者—年份指纹。不同版本映射到一个 canonical work；旧 ID 保留 alias，合并、拆分及日期修正保留来源和 lineage。

技术报告必须绑定 work，不能继续作为孤立事件。模型、数据、代码、benchmark、Demo 与部署保留各自产出类型；关联项目不等于另一个独立研究，合作组织重复展示也不会使全局 work 计数增加。

同行评审按有逐篇官方证据的 canonical work 去重计算，不能把 `venue + year` 数量、会议节目单或作者自述接收数称为“官方评审工作数”。接收决议和正式出版是两个事件，不更改首次公开月份。会议发现、评审与出版的区别另见[扩充协议](/methods/expansion-protocol)。

## 分类与相关性

- 正式纳入的 work 有且仅有一个主 D，D1–D15 表示主要研究贡献。
- 分类平局、最高两项分差不超过 1、缺少可靠主方向的记录进入复核，不由配置顺序强行决定。
- Q0–Q10、方法、能力/任务、本体、数据与模态是可重叠的维度；标签命中不等于能力已经实现。
- 主 D 数量、多标签覆盖和分类待定数分开展示。待复核、候选和排除记录都保留，可在[数据库](/database/)主动查看。
- 研究组 G1/G2 归属不能绕过相关性判断；企业名气、开放代码或正式会议接收也不能自动让无关研究进入 included。

具体边界与局限见[纳排规则](/methods/inclusion)。

设备身份、实际使用关系以及移动与全身操作的专题范围分别核验；详见[研究设备与联合操作](/methods/equipment-loco)。型号未公开、仅被提及、轨迹回放、仿真与真机闭环不互相替代。

## 月份与两种证据视角

默认窗口是最近 12 个完整自然月，当前月附加为暂行列。完整月折线不连接暂行月份；有观测的暂行值用独立点，尚无采集数据的值是未知而不是零。来源失败、无精度日期、未编码能力和零项已核实证据，都不能解释为现实中没有研究活动。

[月度页面](/monthly/)和[趋势页面](/trends/)提供两种不同问题的答案：

| 视角 | 回答的问题 | 统计边界 |
|---|---|---|
| 当月可用证据 `as_of_month` | 当时已公开的信息能支持什么判断？ | 只使用不晚于该月末、且有日期及来源支持的评审、产出和能力证据 |
| 今天回看 `retrospective_evidence` | 同一批当月首次公开研究，后来获得哪些验证？ | 保持研究 cohort 不变，将证据截止延伸到当前数据截止 |

切换会影响严格评审、E 等级、能力证据与具体命题账本，不把未来新论文塞回过去月份，也不改变当月首次出现的工作数。编辑摘要保持其保存时的证据包口径；无时态字段的旧快照不会冒充历史时点证据。数据库详情提供当前已登记版本，不能将详情中的后来成果误读为当月已知。

### 日期精度与修订

确切时间点使用带时区的记录，页面换算为 Asia/Shanghai；仅有日期、月份或年份的来源保留原精度，不补造精确日或时刻。月精度证据只在该月结束后可用于时点判断；年精度证据保守到年末，年份或日期未知的 work 不强塞到某个研究月份。无时区的时间戳不能默认为 UTC。

首次公开日、接收日、出版日、开源日、首次发现日和本次运行日分别保存。官方来源只支持月份时，审核修正仅覆盖指定日期字段、版本及事件；原始观察、被替代值、来源关系和字段 provenance 继续保留。

跨月更新封存完整月，迟到记录、分类修订或证据变化创建新 revision；旧归档可打开，差异记录包含覆盖数量前后值及工作/判断变化。只读导出不会偷偷写入新的权威修订。

## 撤回、撤稿、更正与恢复

状态通知与论文首次公开、接收和出版分别记录。官方通知的发生时间、来源采集时间、受影响 work 和字段出处都保留；网页无法访问、摘要提到撤稿或普通新版本发布都不能被自动当作撤回／恢复证据。

最新状态元数据使用独立于正文覆盖的观测截止日期。因此，即使 arXiv 正文只覆盖到八月底，已登记的九月撤回也必须在当前搜索和详情中提示。月份证据与回看证据仍各自按原截止日期计算；更新的状态另列提醒，不倒灌旧时点。全库状态截止并不表示每篇论文都在同一天重新巡查。

按所选时点已生效的撤回或撤稿，会阻止受影响的结果进入模型叙述证据、趋势支持、反例和成熟度升级；研究活动数量、原文与版本记录不删除，实际已公开的代码／模型／数据资产仍可检索。E0 状态门槛与显式撤回提示配合使用，不代表撤回前没有发生过评审、实验或资产发布。

旧月份保留当时可用的信息；若其中的引用后来发生状态变化，页面单独提示后续通知及受影响判断，并链接官方原文。该提醒不被计作旧月当时已知的证据。更正和关注声明本身不自动等于撤稿；明确恢复须晚于阻断通知，无法判断顺序的冲突保守保留复核。

当前 arXiv 适配器要求官方版本页的状态标记与同版本提交历史相互印证；解析有自动测试，网络或版面不明确时进入复核，不冒充成功采集。批量“已知作品后续更新”的自动检查尚需接入完整周更；仅新增适配器和登记通知不代表互联网状态变化已被全面监控。

## 证据库检索口径

每个 canonical work 只有一条检索记录，包含已采集的标题、摘要、作者、机构和研究标签。存在可验证版次档案时选择截止日前可用的正文；没有版次档案的已采集摘要仍可检索，但标明“版次未核验”，不能用于判断该文本在某个历史月份已经可用。日期未知不会被补成首次公开日。

普通全文检索将连字符、下划线和空格视为分词边界，使用共享的中文分词与英文停用词规则；`cross-embodiment` 和 `cross embodiment` 等价。没有分隔符的拼接拼写不自动等价，除非已在原文或别名字典中登记。可直接粘贴原始标题检索，但不承诺带标点或公式的引号查询逐字符匹配；完整 DOI、URL、work ID 与 π 模型身份在全文分词之前独立解析。

原文不因索引压缩而改写。重复词项压缩不保留原始词频或所有摘要短语位置；检索结果不是论文支持某项结论的证据。原始文本、历史版次和完整来源可从 JSON／SQLite 核对。Pagefind 的传输文件另作标准 gzip 无损重压缩，每份文件都须证明解压后字节一致；这一步不改变分词、排序或研究数据。

## 趋势判定

### 议题动量不等于命题成立

D 方向和关键词检索的数量、份额与动量表示研究活动。具体研究命题必须逐项绑定“支持 / 反对 / 中性”证据、原文片段、实验条件和适用边界。检索命中的论文不自动算作支持证据；没有已审阅支持时保留候选或待审阅状态。

生命周期、议题动量与证据成熟度是三种独立结果，不合成一个总分。当前规则对具体命题采用：

- **新兴**：最近两个月至少 3 项已审阅支持 work、至少 2 个来源簇，并有带日期核实的真机、开放资产、新 benchmark 或部署证据。
- **巩固**：连续 3 个完整月存在已审阅支持，至少 3 个研究组、至少 2 个来源簇，并有严格评审或独立跨平台复现。
- **成熟**：至少 2 个研究组、至少 2 个来源簇，具备真机证据，并覆盖至少两个正式 venue 或有明确独立跨平台复现。
- **上升**：最新完整月的议题份额比此前三月均值至少增长 25%，且新增至少 2 个来源簇；它是议题动量，不单独证明能力提升。
- **降温**：连续两个月份额至少下降 25%，且近期没有新增 E3/E4 验证；不完整月不参与判断。
- 已审阅的支持与反例并存时显式保留争议，不能用总数量覆盖反例。

### 来源簇与独立复现

来源簇只合并明确登记的项目系列，或有 URL 和 verified 审阅记录的共同证据来源/依赖。共用仓库与显著作者重合单独保存为关系，不直接合并来源簇；共用模型、数据或 benchmark 也不能仅凭关键词判为同源，更不能沿共享资源关系传递合并不相关团队。

不同来源簇只是“尚未证实同源”，不是已经证明独立复现。同一公司的不同产品、论文数量、多个合作者、不同学校署名或代码 fork 都不单独构成独立验证。独立复现另需带日期、来源绑定及审阅的记录，明确独立团队和跨平台条件。

## 证据等级

下表作用于有来源与可用日期的 work 证据；纯文本标签和旧布尔标记若缺少证据日期，只显示信息缺口，不自动用于升级。

| 等级 | 当前判定 |
|---|---|
| E0 | 尚无满足以下门槛的已登记可用证据；不等于论文低质量或没有实验 |
| E1 | 企业技术报告或 Demo 的第一方披露，尚无严格评审或独立验证 |
| E2 | 有核实且带日期的真机、开放代码/数据/模型、benchmark 或部署证据 |
| E3 | 严格同行评审，或有来源绑定、独立团队、跨平台条件的复现 |
| E4 | 同时有严格同行评审、真机证据和上述独立跨平台复现 |

企业单方技术报告即使自述真机与部署，也不能单独超出 E1。跨本体、长时序和真机须分别编码，不能用多机构合作替代 E4 的独立复现要求。

## 组织归属

G1 为官方实验室论文/项目页或论文直接声明；G2 为论文作者与带时间的官方成员关系共同支持，必须覆盖 work 日期。G3 为推测待核验；G0 为母机构或归属冲突，不能下钻成具体实验室。

正式组织活动同时要求 G1/G2 与研究相关性通过。档案的完整已归属集合、相关性待审集合与高信号待归属队列分开；无工作不删除组织，母机构没有论文数排行榜。T0/T1/T2 的纳入、来源健康和发现门槛见[研究组方法](/methods/research-groups)与[覆盖审计](/methods/coverage)。

## LLM 编辑与语义复核

当前编辑器接收预先计算的月度证据包，通过 Responses 格式接口请求严格 JSON Schema；校验章节结构、数据库引用、事实 ID、数值与原文片段。关键工作可生成中文标题、摘要和关键词，其余记录保留原文检索，不要求给全部 work 编造中文内容。

模型生成的 `signal_assessments` 必须先保存为 draft。程序检查原文引用的字符范围、逐字内容、来源 URL/ID、公开日期和实验字段，但这些检查不证明“这段实验是否真正支持该命题”。升为 verified 还要显式完成语义复核，记录 reviewer、时间、说明和审阅历史；自动生成不能自行勾选 verified。

[月度页面](/monthly/)的“原文阅读与待审证据”可按需展开已保存的草稿。AI阅读记录明确标注不是人工审阅；没有记录具体模型时保留空值，不冒充本地 Responses 调用。摘要没有提取到对照或指标，只表示这张卡未编码，不表示论文没有实验。全文阅读说明与可逐字验证的摘要摘录分开，草稿数量不计作已验证论文数或独立证据簇。

非arXiv公司报告使用独立的 `report-text-snapshots` 短摘录协议，不伪装成arXiv摘要、不继承CC0。报告标注日期、本次读取时间、正文最迟可用时间分别记录；历史上界只能由内容哈希绑定的档案证明，新抓取页面只能从本次捕获时刻使用。GEN-1.5的官方索引内嵌搜索文本可由八月Git提交中的哈希和部署记录核查，其他缺少正文档案的报告仍只展示元数据与缺口，不用旧中文说明补齐原文。

公司报告的模型叙述保持定性；数值由绑定到短摘录的观测表计算并固定呈现其条件、单位和公司自报属性。即便两个数字都存在，模型也不能把它们对调到不同示教／梯度预算。原文短摘录有总字数限制，上下文说明明确标为AI提取，不冒充逐字引文、完整实验或人工语义批准。

来源内容、证据包或模型变化会使旧编辑缓存失效。失败最多尝试三次，未配置服务不发请求；仍失败则输出明确标注的纯数据版。已保存历史编辑不删除，但失效摘要不会继续覆盖新事实。草稿需重新生成或复核；已核实的历史原文快照可保留，若其来源日期已被明确取代则仍需重新核验。

本机已通过既有 LoggerBot 的本地 Responses 通道生成中文月报；只复用显式配置的模型地址、密钥和模型名，不读取其飞书身份或业务内容。模型密钥不进入网站、数据库或仓库。

每个月是否已生成有效编辑、是否只有纯数据、是否完成后续 AI 内容审校，须分别查看[月度页面](/monthly/)与[编辑运行状态](/api/v1/editorial-status.json)。批量生成成功、引用与数值校验通过，不等于专家审阅或所有趋势命题已验证。AI 修订保留原稿、改动前后内容、理由与证据链接；不能把少量确定性数量摘要视为已完成全面研究分析。

## 下载与复算

- <a :href="withBase('/downloads/radar.sqlite')" download>下载完整 SQLite 数据库</a>；JSONL 仍是可编辑权威层。
- [SQLite 逐表还原清单](/api/v1/sqlite-fidelity.json)：每张权威表的恢复视图、记录数与内容摘要。SQLite 内的 `catalog_fidelity_manifest` 列出 `catalog_restore_*` 标准 SQL 视图；读取 `payload_json` 可还原原始 JSONL 记录，包括缺失键与空值、重复关系、日期精度、归属证据和分类版本。日常查询的扁平业务表不代表完整原始记录。
- SQLite 的 `editorial_artifacts` 单独保存月报、原稿归档、AI 审校、本地化和命题阅读记录；`monthly_editorial` 与 `editorial_narratives` 提供月报及六类叙述章节查询。它们属于生成／审阅层，不与权威库的 `editorial-claims` 或原始中文字段混淆。
- [API manifest](/api/v1/catalog-manifest.json)：版本、语料截止、计数、窗口及分片信息。
- [趋势数据](/api/v1/trends.json)：方向序列、议题动量及具体命题。
- [组织覆盖与待归属](/api/v1/organization-coverage.json)、[来源健康](/api/v1/source-health.json)。
- [命题证据与待审草稿](/api/v1/signal-evidence.json)、[公开事件](/api/v1/evidence-events.json)。
- [撤回、更正与状态通知](/api/v1/research-status.json)：状态来源、日期、当前阻断及待复核线索；各月 JSON 另含受影响的编辑引用清单。
- [公司报告历史短摘录](/api/v1/report-text-snapshots.json)、[按当前截止时间选择的报告证据](/api/v1/report-text-index.json)；SQLite的`report_text_snapshots`保留相同记录及canonical映射。
- `monthly/{YYYY-MM}.json` 及其 `revisions[].url` 可取得当前月与历史归档；`organizations/{slug}.json` 提供完整档案。
- 先用 `aliases.json` 解析历史 ID，再按 SHA-1(work ID) 前两位查 `works/{00–ff}.json`，可重建 work 的全部 manifestation、来源和事件。

[研究数据库](/database/)使用按需加载的 Pagefind 静态索引；中英文别名、D/Q 与组合筛选状态可写入 URL。精确证据集合使用 `ids`，不是把 work ID 当作普通全文查询。站内文章导航搜索与研究数据库搜索是两套索引。
